# 2026-07-18

## Issue #9 — "Folders to exclude" not settable / empty entries

Fixed the excluded-folders settings so folders can be added reliably, and hardened the folder-matching so a stray blank entry can no longer disable the whole plugin.

### Root cause

- The add flow read the field only via `SearchComponent.getValue()` at click time. When the suggester blurred/cleared the field first, that returned `""`, so the "+" button persisted a **blank** entry (the reported "field always goes to empty").
- Matching used `file.path.startsWith(ignoredFolder)`. A blank entry makes `startsWith('')` always true ⇒ **every file treated as excluded** ⇒ no note ever updates. The same loose prefix also mismatched sibling folders (`Journal` wrongly matched `Journal-Archive/…`).

### Changes

- `src/app/utils/is-in-ignored-folder.fn.ts` (new) — centralized, path-segment-aware matcher; skips blank/whitespace entries; tolerates trailing slashes. Spec covers the empty-prefix regression and the sibling-prefix false positive.
- `src/app/plugin.ts` — `shouldFileBeIgnored` now delegates to `isInIgnoredFolder`. Backfill inherits it via `shouldFileBeIgnored`.
- `src/app/settingTab/index.ts` — add handler mirrors the field via `onChange` and a `FolderSuggest` select callback, uses `getValue() || mirror`, trims, and **rejects blank input** (no empty rows, no vault-wide poison).
- `src/app/utils/folder-suggest.ts` — `selectSuggestion` now commits through the base `setValue()` and notifies via an optional `onSelectFolder` callback, keeping the input and listeners in sync (previously set `inputEl.value` directly).
- `src/app/settingTab/index.spec.ts` (new) — regression coverage for add / empty-guard / whitespace / cleared-field-survival / dedupe / remove.
- Business Rules invariant #1 updated (path-segment match, skip blanks, UI rejects blanks).

### Verification

- `bun run tsc`, `bun run lint`, `bun test` (70 pass), `bun run build` all clean.
- **Manual runtime check still needed** (no live vault): in Obsidian settings, add a folder via the "+" button and by picking a suggestion; confirm it persists and appears in the list; confirm typing nothing and clicking "+" adds nothing; confirm notes in excluded folders are skipped while sibling folders are not.

## Issue #6 — assessed, NOT fixed here

Separate, already-diagnosed root cause: timestamps are stored without a timezone offset, so a typed "Date & time" property round-trips through YAML as UTC and breaks the debounce comparison in non-UTC timezones. Unrelated to the #9 empty-entry bug (reporter had no excluded folders). Fix is planned in `documentation/plans/issue-6-updated-not-refreshing.md` (change `DATE_FORMAT` to include an offset + `parseDate` robustness). Left for a dedicated change.
