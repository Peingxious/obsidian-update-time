# 2026-07-17

## Two-phase release workflow (attestation fix)

- Ported the two-phase `release.yml` design from `obsidian-remarkable-sync` (proven live with remarkable-sync 1.5.0: attestation cert sha == tag commit).
- Problem with the old workflow: it built + attested at the triggering commit, then created the version-bump commit and tagged it. The attestation was therefore bound to a different commit than the release tag → Obsidian community-catalog review rejected the release ("attestation failed cryptographic verification").
- New design:
    - `prepare` job (dispatch on a branch): version bump, changelog, format, build + `bun test` gate, commit, lightweight tag, then re-dispatches the workflow at the tag ref with `publish=true`. Idempotent re-runs (detects an existing `chore(release): <version>` commit at HEAD).
    - `publish` job (dispatch-at-tag or bare tag push): `github.sha` == tag commit; builds, attests via `actions/attest-build-provenance@v3` (no `continue-on-error`), creates the release.
- This repo matched the reference template exactly (runner `ubuntu-slim`, `dist/` artifact paths, `release:*` scripts, `git add` list incl. `docs/release-notes.md`), so the port was clean; only the old file's step ordering differed from the shared template.
- Updated `scripts/release.sh` workflow description to match the new phases.
- `bun run format` also normalized two documentation files (`*x*` → `_x_`) that were failing the standing CI `format:check` — committed separately, which fixes the last red CI run.
