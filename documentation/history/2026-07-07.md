# 2026-07-07

## Reported problem

User reports that the auto-refresh of the `created` / `updated` front-matter properties makes some of their CSS stop displaying. Root cause: the live handler writes via `fileManager.processFrontMatter`, which does a full-file rewrite; any write refreshes the open editor and tears down the rendered properties view, so CSS targeting the properties / live editor DOM flickers or disappears. User also asked to improve refresh performance in general.

## Shipped — architecture deepening (all candidates except the speculative one)

Driven by `/improve-codebase-architecture`. Five candidates were reviewed; four implemented, one intentionally deferred.

### Candidate 1 — `FrontMatterWriter` seam (Strong)

Extracted the write mechanism out of `processFile` into an interface + `ProcessFrontMatterWriter` so the "decide what to write" logic (pure `applyTimestampsToFrontMatter`) is fully separate from "how to write". Enables swapping/wrapping the writer without touching decision logic.

- `src/app/utils/front-matter-writer.ts` — `TimestampInput`, `FrontMatterWriter`, `ProcessFrontMatterWriter`.
- `src/app/utils/front-matter-writer.spec.ts` — 2 specs (default keys + custom names).

### Candidate 2 — defer writes for the active note (the style fix)

When the target is the file open in the active editor leaf, the write is deferred (added to `pendingWrites`) and flushed on `active-leaf-change` once the user moves to another note / closes it. Eliminates the re-render-under-the-user that disrupted CSS. All ignore filters and invariants #2/#4/#5 still apply when the deferred write runs.

- `src/app/utils/is-active-file.fn.ts` + `.spec.ts` — pure `isActiveFile(activeFilePath, targetPath)`.
- `src/app/plugin.ts` — `pendingWrites` set, active-note guard in `processFile`, `flushPendingWrites()`, best-effort flush on unload.
- `documentation/Business Rules.md` — new invariant #15.

### Candidate 3 — drop the full-file read (Strong perf win)

`shouldFileBeIgnored` previously called `vault.read(file)` on every debounced change just to test emptiness. Replaced with `file.stat.size === 0` (`isEmptyFile`). No full read per change.

- `src/app/utils/is-empty-file.fn.ts` + `.spec.ts` — pure `isEmptyFile(statSize)`.
- Behavior note: files containing only whitespace are no longer treated as "empty"; negligible, and the common zero-byte case is preserved.

### Candidate 4 — prune the per-file maps (Worth exploring)

`debouncers`, `lastWriteMtimes`, and `pendingWrites` now evict entries on `vault` `delete` / `rename` (via `registerEvent`), so they cannot grow without bound in a large vault.

- `src/app/plugin.ts` — `evict(path)` + new `delete`/`rename` listeners.

### Candidate 5 — surgical frontmatter patch (NOT done)

Marked Speculative in the review: high YAML-format risk and still re-renders the active note, so it adds little once candidate 2 already prevents the disruptive re-render. Deferred intentionally.

## Addendum — i18n layer (2026-07-07, 16:44)

### What was done

Added a full i18n (internationalization) module that auto-detects the system language via `navigator.language` and localizes every user-facing string. No separate language setting — the plugin follows the OS/browser language.

### Files created

- `src/app/i18n/lang.ts` — `LocaleDict` interface with 30 keys, plus `en` and `zhCN` dictionaries covering every user-visible string in the plugin (settings tab titles/descriptions/buttons, backfill confirm modal, backfill command name + notices).
- `src/app/i18n/index.ts` — `detectLocale()` matches `navigator.language` (any `zh*` → Chinese, everything else → English), exports `t(key, vars?)` that substitutes `{{placeholder}}` patterns in templates.

### Files modified

- `src/app/settingTab/index.ts` — all 17 hardcoded strings replaced with `t('key')` or `t('key', { vars })` calls.
- `src/app/ui/backfill-confirm-modal.ts` — all 7 strings replaced.
- `src/app/commands/backfill-properties.ts` — 3 strings replaced (command name + 2 notices).

### Design decisions

- **No setting persisted**: Language is detected fresh on every plugin load. If the user switches their OS language, the plugin follows automatically next time it loads.
- **`t()` takes a `Record<string, string | number>`**: Avoids positional-arg confusion; each `{{name}}` in the template maps to `vars.name` explicitly.
- **Missing key fail-safe**: Unknown keys return `[MISSING: key]` so development errors are surfaced immediately.
- **manifest.json / package.json unchanged**: Plugin metadata (name, description) stays in English because Obsidian's community catalog expects English text.
- **Zero-weight dependency**: No i18n library added; everything is plain TypeScript + a single regex replace.
